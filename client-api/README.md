# Заявки с сайта на почту

Здесь лежит готовый модуль, который дублирует заявки с сайта на почту и пишет
каждую заявку в файл на диске. Сейчас заявка уходит только в Telegram: если бот
или Telegram недоступны, заявка пропадает совсем. Почта - второй независимый
канал, файл `leads.log` - последняя страховка.

**Важно:** сам сервер приёма заявок (`server.js`) живёт не в этом репозитории, а
на машине владельца, в `~/sites/golubev-consulting/client-api/`. Этот модуль нужно
скопировать туда и подключить двумя строками - см. шаги ниже.

## Что делает модуль

При каждой заявке:

1. Пишет строку в `leads.log` (JSON, одна заявка - одна строка). Это происходит
   до всякой отправки, поэтому заявка сохраняется, даже если не ушло ничего.
2. Отправляет письмо на указанный адрес: кто, телефон, почта, направление,
   сообщение, откуда заявка и время по Москве.

Письмо приходит с темой вида «Заявка с сайта: Иван Петров, +7 926 111-22-33» -
видно в списке входящих без открытия. Если клиент оставил свою почту, ответить
ему можно прямо из письма: адрес подставляется в «Ответить».

Модуль не может сломать существующую отправку в Telegram: он никогда не выбрасывает
ошибку наружу, а если не настроен - просто ничего не делает и пишет предупреждение
в лог сервера.

## Шаг 1. Пароль приложения в Яндексе

Обычный пароль от почты для отправки через программы не подходит, нужен отдельный
«пароль приложения»:

1. Зайти на https://id.yandex.ru/security/app-passwords
2. Нажать «Создать пароль приложения», выбрать тип **«Почта»**
3. Назвать, например, «Сайт - заявки», и скопировать выданный пароль
   (16 символов, показывается один раз)

## Шаг 2. Настройки на сервере

В папке `~/sites/golubev-consulting/client-api/` в файле `.env` добавить четыре
строки (файл создать, если его нет):

```
SMTP_USER=golubev-artur@yandex.ru
SMTP_PASSWORD=пароль-приложения-из-шага-1
LEAD_EMAIL_TO=golubev-artur@yandex.ru
SMTP_HOST=smtp.yandex.ru
```

`LEAD_EMAIL_TO` - куда приходят заявки. Можно указать несколько адресов через
запятую, если письма должны видеть не только вы.

Файл `.env` не должен попадать в git: в нём пароль.

## Шаг 3. Установить и подключить

В той же папке на сервере:

```bash
npm install nodemailer@6.9.14
```

Скопировать туда `lead-email.js` из этого репозитория, затем в `server.js`
добавить две вещи.

В начало файла, к остальным `require`:

```js
const { notifyLead } = require("./lead-email");
```

И в обработчик заявки - сразу после того, как заявка принята и разобрана,
рядом с отправкой в Telegram:

```js
notifyLead(lead);
```

Где `lead` - объект с полями `name`, `phone`, `email`, `direction`, `message`,
`source` (ровно то, что присылает сайт). `await` не нужен: письмо уходит
параллельно и не задерживает ответ посетителю.

Перезапустить сервер.

## Шаг 4. Проверить

Сначала проверка самой почты, без сайта:

```bash
node lead-email.js --test
```

Команда покажет текст письма и отправит тестовое на указанный адрес. Если письма
нет - заглянуть в «Спам», там же будет видна причина ошибки в консоли.

Потом настоящая проверка: оставить заявку на https://golubev-consulting.ru/forma
и убедиться, что пришли и письмо, и сообщение в Telegram.

## Если что-то пошло не так

- **«not_configured» в логе** - не заданы `SMTP_USER`, `SMTP_PASSWORD` или
  `LEAD_EMAIL_TO`, либо `.env` не подгружается сервером.
- **Ошибка авторизации** - использован обычный пароль от почты вместо пароля
  приложения из шага 1.
- **Письма нет, Telegram есть** - посмотреть `leads.log`: если заявка там, значит
  до модуля всё дошло и дело только в почте.
- **Не пришло ничего, ни письма, ни Telegram** - значит заявка не дошла до
  сервера вообще. Проверять надо не почту, а доступность самого сервера
  `api.golubev-consulting.ru`.
